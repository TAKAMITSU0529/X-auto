# X AUTO 要件定義 比較分析レポート

**Fable版 v1.0 と ChatGPT版の客観比較、および統合方針の記録**

| 項目 | 内容 |
|---|---|
| 作成日 | 2026-08-15 |
| 目的 | 2つの要件定義を客観的に分析・比較し、`X-AUTO要件定義書-v2.0.md` の統合判断の根拠を記録する |
| 比較対象 | ① Fable版 v1.0（Claude Fable で作成）② ChatGPT版（全73節） |

---

## 1. 結論

**「どちらか一方を選ぶ」のは損である。** 2つは同じプロダクトを別の角度から書いた文書で、優れている領域がほぼ重なっていない。

- **Fable版 ＝ 優れた「エンジニアリング文書」** — 実現可能性・コスト・リスクの管理が強い
- **ChatGPT版 ＝ 優れた「プロダクト文書」** — ビジョン・差別化機能・UX思想が強い

よって **Fable版の骨格に ChatGPT版のプロダクト概念を移植した統合版 v2.0** を確定版とした。

---

## 2. Fable版 v1.0 の分析

### 良い点

| 観点 | 内容 |
|---|---|
| 開発管理性 | 機能ID（F-01〜F-13）＋ S/A/B優先度で管理されており、そのまま開発チケットに落とせる |
| コスト設計 | X API 従量課金の単価目安→月$8〜30 の具体的試算、24時間キャッシュ、ユーザー別クォータまで踏み込んでいる。**ChatGPT版に無い決定的な強み** |
| 検証可能性 | 受け入れ基準（「5分以内に抽出結果が表示される」等）があり、MVP の完成を客観判定できる |
| リスク管理 | スクレイピング禁止・剽窃の類似度チェック・書籍著作権・X自動化ルールを表形式で整理 |
| 計画性 | フェーズごとの期間目安（1.5〜2ヶ月等）がある |
| 誠実さ | 未決事項（§12）を正直に列挙し、ドラフトとしての位置づけが明確 |
| データモデル | カラムレベルの記述があり、ChatGPT版（テーブル名の列挙のみ）より具体的 |

### 弱い点

| 観点 | 内容 |
|---|---|
| プロダクトの勝ち筋 | 機能の列挙はあるが「なぜ競合のAIライティングツールに勝てるのか」の設計（学習ループ・個人化）が薄い |
| UI思想 | 画面一覧はあるが、UXの設計思想への言及がほぼ無い |
| 分析の粒度 | 外れ値検出・HOOK分析・形式分析・独自スコアに相当する機能が無い |
| 本人性の担保 | MY BRAND / Knowledge Base に相当する「本人の一次情報を優先する」仕組みが F-12 のトーン設定程度しかない |

## 3. ChatGPT版の分析

### 良い点

| 観点 | 内容 |
|---|---|
| コンセプト | MODEL → ORIGINAL → LEARN が明確。「使うほど本人専用に進化する（Personal Growth Model）」という競争優位の置き所が正しい |
| 外れ値検出 | Outlier Score（投稿の反応率÷アカウント通常反応率）が秀逸。実装コストが低いのに価値が高い。追加APIコストもゼロ |
| 本人性 | MY BRAND / Knowledge Base（本人の経験・実績・禁止表現を一次情報として優先）—「AIっぽい他人の言葉」にならないための核心 |
| UI思想 | 「数字 → AI解説 → 次にやること」の3段構成、分析→この型で作る→3案→予約が数クリックで完結する AI BUTTON 設計が具体的 |
| AIの誠実さ | AI回答ルール（DATA / HYPOTHESIS / ACTION の区別）と【確実】/【推測】の書き分け。AIが推測を事実のように話すのを防ぐ設計思想 |
| 法務 | センシティブ属性の推定禁止（X Developer Policy）に触れている。**Fable版に欠けていた重要な法務項目** |
| 運用の解像度 | 投稿ステータス管理・コンテンツカレンダー・投稿前AIチェック・週次レポート＋NEXT BEST ACTION・North Star Metric など運用フェーズの設計が厚い |

### 弱い点

| 観点 | 内容 |
|---|---|
| スコープ過大 | 全73節。全部作ろうとすると確実に頓挫する規模。MVP（Phase 1）だけで10項目ある |
| コストの数字が無い | 「APIコスト管理をする」とは書いてあるが、いくらかかるかの試算が無い |
| 検証可能性 | 受け入れ基準・フェーズの期間見積もりが無い |
| 実現性の甘さ | ① Follow Graph 競合探索：followers/following 取得はAPIコストとレート制限が重く、v1では非現実的 ② 全文アーカイブ検索前提：アクセス条件が厳しく、実際は直近7日検索が基本 |
| データモデル | テーブル名の列挙のみでカラム定義が無い |

## 4. 統合方針（v2.0 での採用マップ）

| 領域 | 採用元 | v2.0 での扱い |
|---|---|---|
| 文書構造・機能ID・S/A/B優先度 | Fable版 | 全機能 F-01〜F-25 に再編・付与 |
| X API コスト試算・キャッシュ・クォータ | Fable版 | §7 に継承。BUDGET LIMIT（F-25）として機能化 |
| 受け入れ基準 | Fable版 | §11。Outlier Score・MY BRAND・API上限の項目を追加 |
| リスク・法務表 | Fable版 | §12。センシティブ属性制限（ChatGPT版由来）を追加 |
| フェーズ期間見積もり | Fable版 | §10 |
| コンセプト（MODEL→ORIGINAL→LEARN）・North Star Metric・タグライン | ChatGPT版 | §1 |
| 外れ値検出（Outlier Score） | ChatGPT版 | F-14。**MVPに昇格**（低コスト・高価値のため） |
| X AUTO IMPACT SCORE | ChatGPT版 | F-15（Phase 2） |
| MY BRAND / Knowledge Base | ChatGPT版 | F-17。MY BRAND軽量版をMVPに、Knowledge Base は Phase 3 |
| Content Pillars・投稿比率設計 | ChatGPT版 | F-18（Phase 3） |
| AI LEARNING LOOP / Personal Growth Model | ChatGPT版 | F-19（Phase 2 初版〜） |
| 週次レポート＋NEXT BEST ACTION | ChatGPT版 | F-20（Phase 2） |
| UI思想（数字→AI解説→次の行動、AI BUTTON） | ChatGPT版 | §8 |
| AI回答ルール（DATA/HYPOTHESIS/ACTION） | ChatGPT版 | §9（全機能共通ルール化） |
| 投稿ステータス・カレンダー・投稿前AIチェック | ChatGPT版 | F-07 に統合 |
| センシティブ属性推定の禁止 | ChatGPT版 | §12 に追加 |
| 10項目の投稿分析（テーマ〜反応理由） | ChatGPT版 | F-04 に統合（Fable版の4項目分析を置き換え・拡張） |

### 両版の問題点として修正した点

1. **ChatGPT版のスコープ過大** → フェーズで厳密に絞り、Follow Graph 競合探索は Phase 4 へ明示的に後送り
2. **全文アーカイブ検索前提** → 直近7日検索APIを基本とする（F-11）
3. **非公開メトリクスの30日制限** → 1h/6h/24h/3d/7d/14d/30d の定期スナップショット保存で履歴化（ChatGPT版 §40 の方式を採用し、Fable版の未決事項を解決）
4. **予約投稿のフェーズ不一致**（Fable版=MVP、ChatGPT版=Phase 2）→ **MVPに含める**。リサーチ→生成→予約→計測の一気通貫がプロダクトの核であり、これが動かないと LEARN ループが始まらないため

### ユーザー決定事項（2026-08-15）

| 項目 | 決定 |
|---|---|
| 利用形態 | まず自分専用（シングルユーザー）。DB は user_id を持たせ将来の SaaS 化に備える |
| API 予算 | 未定。BUDGET LIMIT を設定可能な設計とし、実機検証後に確定 |
| 本セッションの成果物 | 統合要件定義 v2.0 の作成まで（実装は次フェーズ） |
