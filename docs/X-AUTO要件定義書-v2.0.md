## 1. プロダクト概要・ビジョン

### 1.1 目的

X運用における「リサーチ → 競合発見 → ヒット投稿抽出 → 勝ちパターン分析 → 市場分析 → ポジショニング → 投稿企画 → 投稿生成 → 予約投稿 → 効果測定 → AIによる改善 → 次の投稿生成」のサイクルを1つのシステムで完結させる。

X AUTOは単なる「AI投稿文生成ツール」ではなく、**X運用の経営・マーケティングOS**である。競争優位は投稿生成AIそのものではなく、「どの投稿を参考にすべきか」「なぜ伸びたのか」「自分なら何を発信すべきか」「実際に何が伸びたのか」を**データで循環させること**に置く。

### 1.2 中心コンセプト：MODEL → ORIGINAL → LEARN

| 段階 | 内容 |
|---|---|
| **MODEL** | 競合・市場の成功パターンを収集・分析する（勘ではなく、実際に反応が取れている投稿データから逆算する） |
| **ORIGINAL** | 成功パターンの**構造だけ**を利用し、ユーザー本人の知識・経験・主張・商品に置き換える（丸パクリではなく構造の転用） |
| **LEARN** | 投稿後の実績を取得し、「このユーザーの場合は何が伸びるのか」を学習する |

これにより、使えば使うほど「一般的に伸びる投稿」ではなく「**この人の場合に伸びる投稿**」を生成できるシステムに進化させる。

### 1.3 コア価値

X AUTOが最終的に提供する価値は「文章を書くこと」ではなく、**XマーケティングのPDCAそのものの自動化**である。

```
RESEARCH（市場を知る）→ STRATEGY（勝つ場所を決める）→ MODEL（勝っている型を知る）
→ CREATE（自分の情報で発信する）→ DISTRIBUTE（継続的に投稿する）
→ MEASURE（数字を見る）→ LEARN（自分専用の勝ちパターンを学ぶ）→ RESEARCH へ戻る
```

### 1.4 成功指標（KPI）

- **North Star Metric**：X AUTO経由投稿の平均成果改善率（導入前比のエンゲージメント率向上）
- 補助KPI：投稿作成時間の短縮（リサーチ〜投稿文完成まで）／週間投稿数・継続投稿率／AI生成→採用率／投稿平均インプレッション／プロフィールクリック・URLクリック（マネタイズ動線への流入）／フォロワー純増／予約投稿率／週次利用率

### 1.5 想定ユーザーと利用形態

- X をビジネス発信・集客に使う個人事業主、経営者、マーケター。コンテンツ販売・コンサル・店舗集客など X からのマネタイズ動線を持つ（持ちたい）人
- **【決定】まず開発者本人専用（シングルユーザー）として構築する。** ただし DB は全テーブルに `user_id` を持たせるなど、将来のクライアント提供・SaaS化（マルチテナント・料金プラン・決済）に耐える設計とする（§13）

### 1.6 タグライン（案）

- 「調べる。考える。作る。投稿する。伸ばす。X運用を、全部ひとつに。」
- 「Xを『感覚』から『データ』に変える。」
- 「伸びる理由を見つけ、自分の言葉に変える。」

## 2. 用語定義

| 用語 | 定義 |
|---|---|
| ベンチマークユーザー | 参考・分析対象として登録する X アカウント |
| モデリング | ベンチマーク投稿の構成・型・キーワード・心理要素を抽出し、別テーマの投稿として再構築すること |
| エンゲージメント | いいね・リポスト・引用・リプライ・ブックマーク・インプレッション等の反応指標 |
| 型（テンプレート） | 投稿の構造パターン（例：問題提起→共感→解決策→CTA） |
| 外れ値投稿（Outlier） | そのアカウントの通常成績と比較して異常に伸びた投稿 |
| ジャンル | 発信テーマの分類（例：AI活用、店舗集客、筋トレ、投資 等） |
| 動線（ファネル） | プロフィール→固定ポスト→LP/LINE/メルマガ等、マネタイズに至る導線 |
| MODEL LIBRARY | 参考にしたい投稿・勝ちパターンを保存するライブラリ |
| Content Pillars | 発信テーマのカテゴリー構成と投稿比率の設計 |
| Personal Growth Model | 本人の投稿実績データから「このアカウントで伸びる要素」を学習した個人化モデル |

## 3. 機能要件

各機能は ID（F-xx）で管理する。優先度：**S=MVP必須 / A=初期リリースに含めたい / B=v2以降**。機能とフェーズの対応は §10 参照。

### F-01. 認証・アカウント管理【S】

- メールアドレス＋パスワードによるサインアップ／ログイン／ログアウト／ログイン状態保持
- パスワードはハッシュ化保存（bcrypt/argon2）、パスワードリセット（メール送信）、メール認証
- X アカウント連携は **OAuth 2.0（PKCE）** で行う。X の ID/パスワードをツールに直接入力・保存させない（規約・セキュリティ上必須）
- 連携画面：接続アカウント表示（@username・アイコン・接続日時・API状態・最終同期日時）、再認証、接続解除
- 将来対応【B】：Googleログイン／Appleログイン／二段階認証／1ユーザー複数Xアカウント連携（マルチアカウント管理）

### F-02. ベンチマーク投稿リサーチ（バズ投稿抽出）【S】

**入力**
- ベンチマークユーザーの @ID／プロフィールURL（またはF-03のリストから選択）
- 取得対象の過去投稿数：20 / 50 / 100 / 300 / 500 / 1000 / 任意指定（※上限は F-25 のクォータ設定に従う）
- 期間フィルタ（任意：直近30日／90日／全期間 ※API取得可能範囲内）
- リプライ・RT を除外するオプション

**処理**
- X API v2 で対象ユーザーのタイムラインをページング取得（レート制限・コスト・取得可能期間の範囲内）
- 各投稿の public_metrics（インプレッション・いいね・リポスト・引用・返信・ブックマーク）を取得・保存

**出力（投稿ランキング）**
- 抽出結果一覧（本文、投稿日時、メディア有無、各メトリクス、元投稿へのリンク）
- ソート基準：インプレッション／いいね／リポスト／引用／返信／ブックマーク／総エンゲージメント／エンゲージメント率／投稿日時／**Outlier Score（F-14）**／**X AUTO SCORE（F-15）**
- CSV エクスポート【A】
- 抽出結果はプロジェクト（ジャンル）単位で保存し、後続の分析・モデリング機能の入力になる

**制約**
- API コスト削減のため、同一ユーザー・同一投稿の再取得は一定時間（既定24時間）キャッシュを利用（§7）

### F-03. ベンチマークリスト管理【S】

- ベンチマークユーザーの登録：@username入力／X URL入力／Xユーザー検索（X APIのユーザー検索を利用）
- 登録情報：アイコン・名前・@username・プロフィール・URL・フォロワー数・フォロー数・投稿数・ジャンル・タグ・メモ・登録日・最終分析日
- リストは複数作成可（例：「AI経営者」「店舗集客系」「文体が好き」）。追加・編集・削除・並べ替え・タグ付け・お気に入り
- リストからワンクリックで F-02 リサーチを再実行、リスト単位の一括分析【A】
- フォロワー数・直近の伸び率などの基本指標をリスト上に表示（【A】定期スナップショットで推移も表示）

### F-04. 投稿AI分析（単体・一括）【S】

**入力**：F-02 で抽出した投稿から、ユーザーが選択した投稿（単体、または 5/10/20/50/100 件の複数選択【一括はA】）

**処理（単体分析）**：各投稿について以下の10項目を生成
1. **テーマ**：何について発信しているか
2. **ターゲット**：誰に刺さる投稿か
3. **インサイト**：ターゲットが心の中で感じている不満・欲求・不安・課題・理想・常識・思い込み
4. **投稿構成**：ブロック単位の構造分解（例：問題提起→常識否定→具体例→解決策→結論）と型の判定（リスト型、ストーリー型、逆張り型、権威型、共感型 等）
5. **HOOK**：最初の1〜2文がなぜ読まれるのか
6. **キーワード**：反応を取っているパワーワード・数字・固有名詞
7. **感情**：刺激している感情（共感・驚き・不安・希望・優越感・危機感・発見・反論・好奇心）
8. **具体性**：数字・実例・固有名詞・ストーリーの使われ方
9. **CTA**：投稿後の行動誘導
10. **反応理由**：「なぜこの投稿が伸びた可能性が高いのか」の説明（心理トリガー：損失回避、社会的証明、好奇心ギャップ、自分事化、意外性 等）

**処理（複数投稿一括分析）【A】**：共通構造／共通HOOK／頻出テーマ／頻出キーワード／感情／CTA／平均文字数／投稿形式の分布（短文・長文・箇条書き・ストーリー・ノウハウ・問題提起・意見・逆張り・実績・事例）＋「このアカウントの勝ちパターンは何か」の横断サマリー

**出力**：投稿ごとの分析カード＋アカウント横断サマリー。分析結果は保存され、F-05/F-06/F-16 の入力になる

**表示原則**：AI分析である以上、因果関係を断定しない。**事実（DATA）と AI推定（HYPOTHESIS）を明確に分けて表示する**（§9）

### F-05. モデリング再生成（型の転用）【S】

**入力**
- モデリング元の投稿（F-02/F-04/F-16 の結果から選択）
- 自分の発信ジャンル・テーマ・言いたいこと・自分の経験・具体例・実績・商品・誘導先・投稿目的・ターゲット
- F-17 の MY BRAND 設定（トーン・禁止事項）を自動参照

**処理**
- 元投稿の「構造・HOOK方式・心理・情報配置・CTA構造」**だけ**を抽出し、内容は本人の「主張・経験・実績・具体例・商品・意見」で完全に再生成
- 文体・一人称・語尾などのトーン指定を反映
- **コピー防止チェック**：類似文章検出・表現類似検出・固有表現検出を行い、元投稿との文面類似度が高い場合は警告して再生成（著作権・剽窃リスク対策。§12 参照）

**出力**：再生成された投稿文（編集可能）。ワンクリックで F-07 予約投稿へ

### F-06. 3案生成＋投稿予測スコア【S（スコアはA）】

**入力**
- 参照する分析結果／モデリング対象の投稿／勝ちパターン（複数指定可）
- 発信ジャンル、今回の投稿で伝えたい内容・目的（認知／共感／教育／販売 等）
- ターゲット設定（F-09 のマーケティング設定があれば自動参照）

**処理**
- 必ず異なるアプローチで 3 案を生成：
  - **A案：反応重視**（HOOKを強くする）
  - **B案：信頼・専門性重視**（深い知見を伝える）
  - **C案：人間性・共感重視**（経験・ストーリー中心）
- 各案に「狙い・想定される反応・推奨投稿時間帯（F-10 の自己データがあればそれを根拠に）」を添える
- 気に入らない案は個別に再生成／トーン調整（もっと短く・もっと攻めて 等）

**投稿予測スコア【A】**
- 「最高の投稿になる」と保証はできないため **AI予測反応スコア** として表示（例：A案 91点／B案 86点／C案 82点）
- 評価軸：Hook / Relevance / Specificity / Novelty / Credibility / Emotion / Readability / Shareability / CTA / Brand Fit
- 本人の投稿実績が蓄積されれば、一般モデルではなく本人データ（F-19 Personal Growth Model）でスコアを補正する

**出力**：3案＋根拠コメント＋（あれば）予測スコア。選択した案は編集→F-07 予約投稿へ

### F-07. 投稿管理・コンテンツカレンダー・予約投稿【S（カレンダー・画像・スレッドはA）】

**投稿管理（S）**
- 自分の投稿をX AUTO内で一元管理。ステータス：アイデア→下書き→AI生成→修正中→承認済み→予約→投稿済み→再利用候補

**予約投稿（S）**
- 日時指定での予約投稿（連携済み X アカウントへ API 経由で自動投稿）。MVPはテキスト＋URLから開始
- 予約状態：Scheduled → Posting → Published / Failed
- 投稿失敗時：自動リトライ＋エラー記録＋ユーザー通知（メール／アプリ内）
- 予約一覧（リスト表示）、編集・削除・下書き保存
- **すべての投稿はユーザー承認を経て行う**（完全自動投稿はしない。§12 の自動化ルール準拠）

**コンテンツカレンダー【A】**
- 月・週・日カレンダー表示。ドラッグ&ドロップで投稿日時変更
- おすすめ時間帯サジェスト（F-10 の自己分析データに基づく）

**拡張【A】**
- 画像添付、スレッド（ツリー）投稿の予約
- **投稿前AIチェック**：読みやすさ／誤字／HOOK／冗長性／ターゲット適合／ブランド適合／CTA／類似投稿・重複／リスク表現 をチェックし、「このまま投稿」「AIでもっと強くする」を選択可能に

**制約**
- X の自動化ルールに準拠（同一・実質同一コンテンツの複数アカウント投稿等の禁止事項をシステム側でブロック）

### F-08. 競合発見エンジン（周辺競合リサーチ）【A】

**入力**：ベンチマークユーザー（1名以上）またはジャンルキーワード

**処理**：以下の手段で同ジャンルの競合アカウントを発見する
- **A. Keyword**：プロフィール・投稿キーワード検索、ハッシュタグ検索、bio のキーワード類似性
- **B. Engagement Graph**：ベンチマークの投稿に高頻度で絡む（引用・リポスト・メンション・返信する）アカウント
- **C. Semantic Similarity**：投稿内容の意味的類似性（AI判定）
- **D. Follow Graph【B】**：フォロー・フォロワーの関連性 ※followers/following 全取得は APIコスト・レート制限が重いため v1 では実装しない（§7）

**出力**
- 競合候補ごとに：フォロワー数・投稿頻度・平均エンゲージメント・発信テーマの要約
- **COMPETITOR SCORE**：候補競合を0〜100で評価（Genre Similarity / Audience Similarity / Content Similarity / Engagement / Growth Signal / Monetization Similarity / Positioning Similarity）
- ワンクリックでベンチマークリストへ追加／F-02 リサーチ実行

### F-09. マーケティング戦略AI（AI Marketing Strategist）【A】

普遍的なダイレクトレスポンス／顧客中心マーケティングの原則（ジェイ・エイブラハムの思想を含む）をフレームワーク化した対話型アドバイザー。**書籍本文の転載は行わず、考え方を X マーケティング実行用の独自フレームワークとして実装する**（§12）。

**設定ウィザード（WHO / WHAT / WHY / HOW）**
- WHO（誰に）：TARGET DESIGN — 業種・年齢層・役職・売上規模・企業規模・課題・欲求・悩み・不満・不安・理想・購買障壁・既存代替手段・情報収集方法・意思決定理由
- WHAT（何を）：提供価値・商品・USP
- WHY（なぜ自分なのか）：実績・専門性・独自性
- HOW（どう伝えるか）：発信トーン、コンテンツの柱、動線設計

**CUSTOMER INSIGHT**
- 表面的なターゲット像ではなく「本人が言葉にしていない本音」まで仮説化：表面的課題／本当の課題／感情／恐れている未来／欲しい未来／行動しない理由／購入しない理由／信じている常識／壊すべき常識
- **AIによる心理推定は事実として扱わず、必ず「マーケティング仮説」と表示する**（§9）

**MARKETING PLAYBOOK（アドバイス機能）**
- ターゲット市場／USP／顧客価値・顧客視点／Strategy of Preeminence／リスクリバーサル（不安の除去）／LTV・継続購入・クロスセル・アップセル／紹介・JV提携／見込み客育成／オファー・CTA／テストと改善／既存資産活用
- リストマーケティング動線の設計：X → リスト化（LINE／メール／コミュニティ／セミナー／無料相談／資料DL／無料診断）→ 関係構築（教育）→ 商品
- CUSTOMER JOURNEY：ターゲットを認知→興味→信頼→比較→相談→購入に分類し、投稿ごとに「どの段階の人向けか」を設定
- 投稿生成（F-05/F-06）はこの設定を常に参照し、「誰に・何を・どんなふうに」がぶれない投稿を出力する

### F-10. 自己投稿分析ダッシュボード【S（基本表示）／A（拡張分析）】

**データ取得（S）**
- 連携アカウントの投稿ごとに：投稿日時・テキスト・インプレッション・いいね・リポスト・引用・返信・ブックマーク・URLクリック・プロフィールクリック・エンゲージメント率
- ※URLクリック・プロフィールクリック等の非公開指標は自分の投稿についてのみ取得可能で、**現行 X API では一部非公開指標に30日制限がある**。そのため投稿後 1時間／6時間／24時間／3日／7日／14日／30日 のタイミングでスナップショット保存し、履歴化する（取得不可の指標は代替指標で対応。§13 実機検証項目）

**基本表示（S）**：投稿一覧＋各メトリクス＋エンゲージメント率

**拡張分析【A】**
- 時系列グラフ（フォロワー推移、インプレッション推移）
- **TIME ANALYSIS**：曜日×時間帯ヒートマップ。本人実績から BEST POST TIME を計算
- **CONTENT ANALYSIS**：テーマ別の平均エンゲージメント率比較（投稿には F-04 の型・テーマ分類を自動タグ付け）
- **HOOK ANALYSIS**：書き出し分類（数字型・質問型・断言型・失敗談型・常識否定型・ニュース型・体験談型）ごとの成績比較
- **POST FORMAT ANALYSIS**：投稿形式（短文・長文・箇条書き・ストーリー・How-To・ケーススタディ・オピニオン・Before/After）ごとの成績比較

### F-11. ジャンル・トレンド分析【A】

**入力**：ジャンル（キーワード群）。例：「生成AI」

**処理**
- 指定ジャンルの直近の高反応投稿を X API 検索で収集（**基本は直近7日間の検索APIを使用**。完全アーカイブ検索はアクセス条件・コストが厳しいため前提にしない）
- 関連投稿・関連ユーザー・頻出キーワード・急増キーワード・話題・発信形式を AI が分類・要約

**TREND RADAR**：ジャンル内トピックを4分類
- Rising Topics（急激に伸びているテーマ）／Evergreen Topics（継続的に伸びるテーマ）／Saturated Topics（競合過多）／Opportunity Topics（需要があるのに発信者が少ないテーマ）

**出力**：トレンドレポート＋投稿ネタ候補リスト。ネタ候補はワンクリックで F-06 の入力へ

### F-12. ポジショニング分析 & プロフィール生成【A】

**入力**：ジャンル、自分の強み・実績・提供できる価値（F-09/F-17 の設定を参照）

**処理**
1. F-08/F-11 の結果からジャンル内の競合ユーザーを一覧化（フォロワー規模・発信テーマ・投稿量・平均反応・高反応テーマ・CTA・URL・商品・ポジショニング）
2. **COMPETITOR MAP**：競合を2軸でマッピング（例：初心者向け↔上級者向け × 情報発信↔実務導入。AIが最適な軸を提案）
3. 空きポジション・差別化可能な立ち位置の仮説を提案（例：「AIニュース発信者は多いが、中小企業向けに実際の業務改善事例を発信している経営者ポジションは比較的少ない」）
4. **POSITIONING SCORE**：ポジショニング候補を複数生成し採点（競合密度／市場需要／差別化／本人実績／本人専門性／マネタイズ可能性／継続発信可能性）
5. **PROFILE GENERATOR**：選んだ立ち位置に基づくプロフィール一式を **3パターン** 生成 — 名前欄（肩書き）／bio／USP／CTA／固定投稿案／ヘッダー文言／プロフィールリンク誘導

**出力**：ポジショニング提案レポート＋プロフィール案（編集可）

### F-13. 競合マネタイズ動線分析【B】

**入力**：F-08/F-12 で抽出した競合ユーザー

**処理**
- 各競合の**公開情報**（プロフィール・プロフィールURL・固定投稿・投稿内URL・CTA・商品名）から収益導線を分析。リンク先（lit.link、LINE、メルマガLP、note、公式サイト等）を辿り分類：コンテンツ販売／コンサル・スクール／店舗集客／SaaS／講座／セミナー／コミュニティ／広告・アフィリエイト／採用 等
- **FUNNEL MAP**：推定導線を図式化（例：X投稿→プロフィール→無料資料→LINE公式→無料相談→研修→導入）
- 「認知投稿→教育投稿→募集投稿→リスト誘導→販売」のような発信フローのパターンを分析

**出力**：競合ごとの動線マップ＋「自分が転用するならこの動線」という提案

**制約**：収益額・成約率など非公開情報は推測しない。**必ず「確認済み」と「推定」を区別して表示する**（§9）

### F-14. 外れ値投稿検出（Outlier Score）【S】

X AUTO の最重要機能の一つ。「10万いいねだから強い」ではなく、**そのアカウントの普段の成績と比較して異常に伸びた投稿**を抽出する。

- **Outlier Score ＝ 投稿の反応率 ÷ そのアカウントの通常反応率**
- 例：通常いいね率 0.5% のアカウントで、投稿Aが 0.6%（1.2倍）、投稿Bが 3.5%（7倍）→ 投稿Bを強いモデリング候補とする
- F-02 のランキングのソート基準・フィルタとして提供。取得済みデータから計算できるため追加APIコストゼロ

### F-15. X AUTO IMPACT SCORE【A】

投稿を横断比較するための独自スコア（0〜100）。

- 構成要素：Like / Reply / Repost / Quote / Bookmark / Impression の各スコア＋Engagement Rate＋Account Baseline＋Outlier Score＋投稿経過時間
- 単純合算ではなく、アカウント規模・インプレッション数・通常成績で補正する
- 表示例：「X AUTO SCORE：92 / 100」

### F-16. MODEL LIBRARY & WINNING PATTERN【S（保存）／A（自動生成）】

**MODEL LIBRARY（S）**
- 参考にしたい投稿を分類タグ付きで保存：HOOK／構成／ストーリー／CTA／教育／共感／権威／問題提起／セールス／逆張り／ノウハウ

**WINNING PATTERN【A】**
- 複数投稿の一括分析（F-04）から勝ちパターンを自動生成し、テンプレートとして保存
- 例：「意外な事実→理由→実例→教訓（平均反応率：高）」「失敗談→気づき→再現可能な方法（中高）」「常識否定→新しい考え方（高）」
- 保存したパターンは F-05/F-06 の生成入力として指定できる

### F-17. MY BRAND & KNOWLEDGE BASE【S（MY BRAND軽量版）／B（KNOWLEDGE BASE）】

**MY BRAND（S・軽量版をMVPに含める）**：生成品質に直結するため初期設定ウィザードで登録する
- 基本情報：名前・職業・会社・事業・経歴・専門分野・強み・実績・商品・サービス
- 発信スタイル：強め／優しい／専門家／経営者／カジュアル／熱量高め／論理的／ユーモア／ストーリー型
- 禁止事項：言いたくない表現・扱わないテーマ・避ける言葉・誇張禁止
- F-05/F-06 の生成は常にこの設定を参照する

**KNOWLEDGE BASE【B】**：本人固有の情報を蓄積する
- 自分の考え方・経験・失敗談・成功事例・顧客事例・商品情報・会社情報・過去投稿・プレゼン・ブログ・YouTube文字起こし・メモ
- **投稿作成時には競合投稿よりも Knowledge Base を一次情報として優先**し、「他人の言葉ではなく本人の発信」にする

### F-18. CONTENT PILLARS・投稿比率設計【A】

- 発信テーマをカテゴリー化し比率を設計（例：AI経営30%／AIツール20%／経営15%／業務改善15%／事例10%／人間性・価値観10%）
- 投稿を目的別にも分類：Reach（新規獲得）30%／Authority（専門性）25%／Trust（人間性・実績）20%／Education（教育）15%／Conversion（商品導線）10%（比率はユーザー調整可）
- AIが実際の投稿比率とのズレを管理し、カレンダー（F-07）とネタ提案に反映する

### F-19. AI LEARNING LOOP / Personal Growth Model【A】

X AUTO 最大の競争優位となる部分。

- 投稿するたびに INPUT（投稿内容・HOOK・構成・テーマ・投稿時間・ターゲット・CTA）と RESULT（インプレッション・エンゲージメント・プロフィールクリック・URLクリック）を保存
- AI が INPUT → RESULT の関係を分析する
- 一定量のデータ蓄積後、「X全体では何が伸びるか」より「**このアカウントでは何が伸びるか**」を優先する（Personal Growth Model）
- F-06 の予測スコア補正、F-20 のレポート、F-21 の AI INSIGHT の根拠データとなる

### F-20. 週次AIレポート & NEXT BEST ACTION【A】

- **AI GROWTH COACH**：毎週AIがレポートを生成 — 投稿数／インプレッション増減／プロフィールクリック増減／ベスト投稿と伸びた理由／来週増やすテーマ・減らすテーマ
- **NEXT BEST ACTION**：分析だけで終わらず「次に何をするか」を必ず提示する
  - 例：「明日は『AI社員導入事例』を投稿してください」「この投稿を別HOOKで再構成してください」「20時台に投稿してください」「このテーマを3投稿シリーズにしてください」

### F-21. メインダッシュボード【S（基本）／A（AI INSIGHT）】

ログイン直後に「**今日何をすればいいか**」が一瞬で分かるUIにする。

- **TODAY**：今日の予約投稿・投稿予定時間・未承認投稿・AIおすすめ投稿・今日狙うテーマ・注目トレンド・競合急上昇投稿
- **PERFORMANCE**：7日/30日インプレッション・エンゲージメント・フォロワー増加・プロフィール流入・URLクリック・投稿数
- **AI INSIGHT【A】**：例「最近『AI社員』をテーマにした投稿の反応率が通常投稿より高いです」「具体的な数字から始まる投稿の平均反応率が高くなっています」「19〜21時投稿の成績が現在最も高くなっています」

### F-22. AI CHAT【B】

全データにアクセスできる対話型AI「X AUTO AI」。
- 質問例：「最近何が伸びてる？」「自分は何について発信すべき？」「この競合が伸びている理由は？」「来週7投稿考えて」「この投稿を自分風にして」「自分の弱点は？」「プロフィール改善して」
- 回答は必ず §9 のルール（DATA / HYPOTHESIS / ACTION）に従う

### F-23. AUTO CONTENT PLAN【B】

- 「今月30投稿作る」と指示すると、AIが市場・競合・本人実績・ターゲット・Content Pillars から月間投稿計画を設計し、カレンダーに配置する

### F-24. 検索・フィルタ【A】

- すべての投稿データを横断検索：アカウント／キーワード／ジャンル／日付／いいね／インプレッション／ER／X AUTO SCORE／投稿タイプ／AIタグ／保存済み／使用済み

### F-25. APIコスト管理・BUDGET LIMIT【S】

- **API USAGE**：今日／今月／予想月額、投稿Read数、User Read数、AI分析回数を可視化
- **BUDGET LIMIT**：ユーザーが月額上限・警告ライン・機能別取得数制限を設定可能。上限到達時は取得系機能を自動停止し通知
- **【決定】月額予算は未定のため、上限値は設定可能な設計とし、実機検証後に既定値を確定する**（§13）
- X 側の spending limits（前払い・支出上限）も必ず設定する（§7）

## 7. 外部 API と運用コスト（重要）

### 7.1 X API（2026年時点の前提）

X API は従来の月額プラン中心から**従量課金（Pay-Per-Use）中心に移行**しており、新規は原則従量課金となる。料金は変更される可能性があるため **Developer Console / docs.x.com の最新料金を正とし、実装前に必ず再確認する**。

- 目安単価：読み取り 1件 $0.005〜0.01、自分の投稿の読み取り（Owned Reads）約 $0.001、投稿作成 1件 $0.01〜0.015、URL付き投稿は割高（約 $0.2）
- **前払い制・支出上限（spending limits）を必ず設定する**
- レート制限はエンドポイント単位。API アクセス層でレート制限ハンドリングを実装する

**コスト試算（例：1ユーザー・月間）**
- ベンチマークリサーチ：200件取得 × 週2回 ≒ 1,600 reads ≒ $8〜16
- 自己投稿メトリクス取得（Owned Reads・スナップショット）≒ 数百件 ≒ $1 未満
- 予約投稿：60件/月 ≒ $1 前後
- → 通常利用で月 $10〜30 程度に収まる想定。ただし**トレンド検索（F-11）・競合一括分析（F-08）・Follow Graph 探索は読み取り件数が膨らみやすい**ため、機能ごとに取得件数上限とユーザー別クォータを必須とする（F-25）

### 7.2 キャッシュ設計

- 同一競合の同一投稿を何度もAPI取得しない。post_id・metrics・fetched_at を DB へ保存し、一定時間（既定24時間）内は DB データを利用
- ユーザーオブジェクト・検索結果も同様にキャッシュ

### 7.3 AI API

- 分析・生成は Claude API を使用。1回の分析/生成あたりのトークン量を設計時に見積もり、生成回数の目安・上限を F-25 で管理

### 7.4 禁止事項（設計上の前提）

- **スクレイピングによるデータ取得は行わない**（X 利用規約違反。アカウント凍結・法的リスク）。データ取得はすべて公式 API 経由とする
- X の自動化ルールに抵触する機能は実装しない：スパム投稿／大量自動返信／自動大量フォロー／同一・実質同一コンテンツの大量投稿の禁止、API レート制限の遵守、投稿は必ずユーザー承認を経る

## 9. AIの回答・表示ルール（全機能共通）

AIが推測を事実のように話すことを防ぐため、AIの出力は必ず以下の3種類を区別して表示する。

| 区分 | 内容 | 表示例 |
|---|---|---|
| **DATA** | 確認できた事実（APIで取得した数値・公開情報） | 「この投稿のERは4.2%で、このアカウントの平均の3.7倍です」 |
| **HYPOTHESIS** | AIによる仮説・推定（心理推定・伸びた理由・ポジショニング仮説など） | 「実体験＋具体的数字が要因候補です（AI推定）」 |
| **ACTION** | 次に行う行動の提案 | 「同じ型で次の投稿を作る」 |

- 心理推定（F-09 CUSTOMER INSIGHT 等）は必ず「マーケティング仮説」と明示する
- 競合の収益分析（F-13）は「確認済み」と「推定」を区別し、非公開情報（収益額・成約率）は推測しない
- 事実主張を含む生成投稿には「事実確認してから投稿」の注意表示を出す

## 11. 受け入れ基準（MVP）

1. メール＋パスワードでサインアップ・ログインでき、X アカウントを OAuth 2.0 で連携できる
2. ベンチマーク @ID と取得件数を指定して実行すると、5分以内にメトリクス付きの抽出結果がランキング表示される（いいね順等でソート可能）
3. 抽出結果に **Outlier Score** が表示され、「そのアカウントの通常比で伸びた投稿」を降順で確認できる
4. 抽出投稿を選んで「分析」を押すと、テーマ・ターゲット・構成・HOOK・キーワード・感情・CTA・刺さる理由が日本語で表示され、事実と AI 推定が区別されている
5. MY BRAND（基本情報・発信スタイル・禁止事項）を設定でき、以後の生成に反映される
6. モデリング元とジャンル・伝えたい内容を入力すると、投稿文 **3案**（反応重視／専門性重視／共感重視）が生成され、うち1つを編集して日時指定で予約 → 指定時刻に実際に X へ投稿される
7. 元投稿と酷似した生成文には警告が表示される
8. 自分の直近投稿のインプレッション・いいね・リポスト・返信等が一覧で確認でき、スナップショットが定期保存されている
9. Settings で当月の API 利用量と推定コストが確認でき、設定した上限に達すると取得系機能が停止・通知される

## 12. リスク・法務上の注意

| リスク | 対応 |
|---|---|
| X API の仕様・料金変更 | API アクセス層を抽象化し変更に強い設計に。料金は毎月モニタリング。Developer Console の料金を正とする |
| 規約違反によるアプリ・アカウント停止 | 公式 API のみ使用（スクレイピング禁止）、自動化ルール準拠（スパム・大量自動操作・同一コンテンツ複数投稿の禁止）、レート制御、投稿は必ずユーザー承認を経る |
| 生成文が元投稿の剽窃になる | 類似文章・表現・固有表現の検出＋警告＋再生成。UI 上でも「構造の転用であり文面コピーは不可」と明示。競合から使うのは構造・HOOK方式・心理・情報配置・CTA構造のみ、内容は本人の主張・経験・実績・具体例・商品・意見のみ |
| **センシティブ属性の推定禁止** | X Developer Policy により、X データから健康・政治的信条・人種・宗教・性的指向などセンシティブ属性を推定・保存することは制限されている。競合分析は発信ジャンル・ポジショニング・公開商品・公開CTAなど**マーケティング上必要な公開情報のみ**を対象とする |
| 書籍内容の著作権 | ジェイ・エイブラハム等の書籍本文は転載せず、一般的フレームワーク・考え方として独自実装する |
| AI 生成の誤情報 | 事実主張を含む投稿には「事実確認してから投稿」の注意表示。AI出力は DATA/HYPOTHESIS/ACTION を区別（§9） |
| API コスト暴走 | ユーザー別クォータ、BUDGET LIMIT（F-25）、X 側 spending limits、キャッシュ（§7.2）、非同期ジョブでの件数制御 |
| 非公開メトリクスの30日制限 | 投稿後 1h〜30d の定期スナップショットで履歴化し、30日超のデータも自前DBに保持 |
